# Trades and Today

Build 5 adds one versioned trade slot per verified series and store. Staff explicitly open a random box into a known design, inspect a customer's same-series item, then confirm the physical swap. Direct sale consumes the exact slot unit through an existing reviewed sale and leaves the slot visibly empty until staff choose an explicit replacement. Request keys and resource versions make retries safe and stale work fail without a second stock movement.

Confirmed-design purchases are ineligible for trade, so original-receipt proof is rejected by the trade intake. A reviewed legacy sticker can create an inspected unit; prior-trade proof must name an existing eligible customer-held unit and reuses that physical identity. Neither path creates a fabricated receipt or customer registration. Condition disclosure is frozen on a direct sale. Condition claims and manager decisions do not issue refunds or change stock.

Condition photos are decoded, normalized, stripped of metadata, stored privately under `popcore_app/uploads/condition_evidence`, and served only after case ownership or scoped manager checks. Backups must copy the SQLite database first, then both `uploads/payment_evidence` and `uploads/condition_evidence`. Record object ID and byte size manifests from each evidence table and verify each referenced file after restore. Quarantine unreferenced files for review; Build 5 does not define deletion or retention.

Today is calculated from current source documents and filtered on the server by the signed-in role and explicit inventory access. Viewer/staff responses omit tender totals, cash variance, evidence identifiers, and other staff's private details. All Stores includes authorized stores only. Personal shifts use the existing `/api/schedule/shifts/me` read with `store_code=ALL`, remain independent from the selected operations store, and appear first for staff. Today refreshes on page load; personal shifts also refresh when the window regains focus.
